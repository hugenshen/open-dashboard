## 背景

对话能力是从「对标内测文章」开始的。后续最大的产品事故是把三种用户意图做成一种生成：

- 问一句数（P006）被做成整页看板
- 生成/改看板（P004/P015）在聊天里出简化条形图，和编辑器 ECharts 不是一回事
- 要一份归因报告（P016）被当成 Dashboard draft

用户原话包括：问数结果后面不要直接生成仪表盘；改图要精准更新同一张板，不要堆很多草稿；分析报告在右侧预览 HTML/MD 文件，不是可刷新看板。

## 解决方案

三条轨，路由先于工具：

| 用户要 | 提案 | 结果形态 | 不要做成 |
|--------|------|----------|----------|
| 先看数 | P006 | 会话内表/临时图 | 整页看板、保存到仪表盘（adopt 延后） |
| 做/改一张板 | P004、P015 | draft 看板 + 可进编辑器 | 只在聊天里画示意图 |
| 写分析报告 | P016 | 右侧 HTML/MD 快照 | JoyAgent 10k/90s 原样搬来；出板 |

表面已迁到 dsh Web（P011）。Python harness 已删。实现对照该提案开发入口，不要从最新 hi-fi 猜。

历史对话（P014）必须按 userId+workspaceId 持久化。用户切换菜单再回来，追加的问题不能丢。

从数据市场/工作台带着数据集进来时，对话框要有选中标识，后续查询用这个数据集，不要再让用户猜。

## 经验总结

- Auto/Plan/生成风格如果产品没用，不要暴露在 UI 上。用户看不懂就等于噪音。
- 思考过程要能看见，但**没完成不要展示终态卡片**；已思考默认不要折叠出大片空白。
- 问数失败、0 行、绑定闸拒绝，要用人话说明，不要只说「技术问题走看板通道」。
- 改图 = 在已生成的板上 replace/append，禁止每次新开一份 draft 仪表盘。
- 默认规则规划（LLM 没配时吐 6 张基础图）质量差，用户会认为「效果不行」。规划必须走 LLM，再做质量检测。
- dsh 与 Java 的 API key 应共用配置；「规划 LLM 没配」但 harness 能聊，是配置分裂。
