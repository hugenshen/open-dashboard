01 · Product positioning

不是替代关系，是入口与专业系统的协作

DataQ 不需要重新做一个通用 AI 桌面，WorkBuddy 也不需要重建一套 BI 治理系统。两者通过清晰分工，把“用户一句话”接到“可信、可追溯、可继续经营的数据资产”。

WorkBuddy 的定位

全场景 AI 工作台

面向普通职场人，以自然语言承接目标，调用专家、Skill 和 Connector 完成跨工具任务，并把过程和产物带回用户日常工作入口。

DataQ 的定位

可嵌入的智能 BI 与分析底座

面向分析师、业务读者和报告作者，用数据集治理查询语义，用草稿/发布态管理资产生命周期，让数据结果可复用、可校核、可发布。

WorkBuddy 的任务入口与智能体编排＋DataQ 的可信数据与 BI 资产能力＝会交付的数据工作搭子

02 · Who it serves

四类用户，一条从提问到发布的链路

01

业务读者

在 WorkBuddy 里直接问经营指标、看可信摘要；需要深入时打开 DataQ 已发布看板。

02

分析师

从可问数据出发生成查询、图表或看板草稿，再进入 DataQ 精编与发布。

03

报告作者

发起归因和解读任务，接收分析产物；正式报告继续在 DataQ 维护与发布。

04

管理员 / 接入方

安装连接、映射身份和工作区；数据治理、权限与审计仍由 DataQ 统一执行。

03 · What DataQ brings

DataQ 提供的是一条完整的数据产品链，而非零散工具

核心治理原则是：业务数据先进入数据集语义层，再被查询、编排和发布；样式不进入查询，编辑态不等于发布态。

05 · User journeys

用户看到的是自然协作，背后仍有专业边界

业务读者问一个经营问题
WORKBUDDY识别“问数”意图并组织问题
DATAQ在授权数据集中查询并返回口径
交付结果摘要 + 来源 + DataQ 深链
分析师做一张经营看板
WORKBUDDY呈现规划并向用户确认
DATAQ基于真实数据创建可编辑草稿
交付草稿链接；精编与发布回 DataQ
报告作者解释业绩波动
WORKBUDDY拆解分析任务并展示过程
DATAQ受控取数、生成分析与证据
交付带时点的报告产物；不冒充 live 看板

06 · How to open capabilities

先做 Connector，再逐步包装专家与行业应用

WorkBuddy 官方对已有 API 服务优先推荐 MCP + Skill。它也最符合 DataQ 的现状：保留专业产品与服务端治理，只把稳定能力开放给 Agent。

首期推荐

Connector

用 MCP 暴露 DataQ 能力，用 Skill 说明触发条件、参数、风险确认和错误恢复。

适合：能力接入与市场分发
第二阶段

数据分析专家

把行业提问方法、分析流程和 DataQ Connector 依赖包装成可召唤的专业角色。

适合：降低用户提问门槛
成熟后

Buddy 应用

将工作模式、专家、Skills、Connector 和已有 DataQ 页面组合为垂直数据工作台。

适合：完整行业解决方案
反向链路

Third-Party App

用于 DataQ 经 OAuth 调用 WorkBuddy 的任务、会话或产物 API，不是首期“能力开放出去”的主链。

适合：DataQ 主动调用 WorkBuddy

07 · Honest capability status

对外介绍要区分：已经有、正在做、准备开放

DataQ 已交付基线

  • 数据库数据源与数据集建模
  • 仪表盘编辑、取数、发布、分享与 CSV
  • 在线报告、插入看板图和实时取数
  • 可插拔身份与模块写权限

DataQ 在途能力

  • 完整的对话问数产品闭环
  • 可解释、可修改的对话式出板
  • 对话分析报告与过程工作区
  • 工作区、资源 ACL 与知识治理完善

WorkBuddy 开放待建设

  • DataQ MCP Connector 与 Skill
  • 跨产品身份 / 工作区映射
  • 结果卡、来源与 DataQ 深链
  • DataQ 数据分析专家 / Buddy 应用

08 · Product boundaries

开放能力，不开放治理缺口

我们要做

  • 让用户在 WorkBuddy 中发现、调用 DataQ 的受控分析能力。
  • 所有查询继续经过 DataQ 数据集、权限和查询链路。
  • 结果带数据集、筛选/时点边界与可继续工作的深链。
  • 写入前确认；AI 生成只落草稿，发布回 DataQ 完成。

我们明确不做

  • 不把 WorkBuddy 当 DataQ 编辑器的完整复制品。
  • 不让 Agent 直接连接业务库或绕过数据集生成裸 SQL。
  • 不把 WorkBuddy 通用文件能力包装成 DataQ 自有能力。
  • 不跨工作区、不默认提权、不在失败时生成“看起来正确”的结果。

09 · Suggested rollout

从可信问数开始，用三步验证真实价值

READ FIRST

只读可信问数

完成连接、身份与工作区映射；只开放资源发现、数据集问数、来源披露和深链。先证明“问得到且可信”。

CONTROLLED WRITE

受控内容生产

在用户确认和权限校验后创建看板草稿；分析报告以带时点的产物返回。先草稿，后发布。

ECOSYSTEM

专家与 Buddy 应用

把高频行业场景、分析方法与 DataQ Connector 组合成专家；成熟后形成开箱即用的垂直应用。

一句话怎么介绍这次合作？

“DataQ 把企业受治理的数据、分析方法和 BI 资产能力开放给 WorkBuddy；用户无需离开日常 AI 工作入口，就能可信地问数、发起分析并获得可继续编辑和发布的专业结果。”更短版本：WorkBuddy 让 AI 会干活，DataQ 让数据工作有事实、有边界、有资产。
