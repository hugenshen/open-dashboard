5. 仍需继续优化的商用项

  1. 真实订单表目录接入：本地 8080/8082 直接访问 /api/internal/bi/datasets 返回空，实际 run 仍使用 ds_sales。需要让 DSH 在同一登录/工作区上下文下稳定拿到 ds_012eb19e · t_pay_order。
  2. 外层/DSH 会话同步：直连 DSH 和外层 iframe 对同一 run 的可见状态不一致；外层应该能主动恢复 progress，不只依赖 postMessage。
  3. trace 持久化：当前 progress 是进程内内存，DSH 重启或新会话会变 idle。localStorage 只能兜底单浏览器，商用仍应落会话事件表。
  4. 真实报告质量 golden case：必须用 t_pay_order 跑出包含商户、支付状态、金额、利润、渠道/时间等真实实体的报告，再和 JoyAgent 样例做章节和证据对比。
