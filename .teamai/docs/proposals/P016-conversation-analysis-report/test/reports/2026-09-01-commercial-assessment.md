## 商用品质缺口

### P0：必须在验收前补齐

1. **真实浏览器全栈 E2E 还未完成**  
   需要在 Docker/后端可用时，从 `http://127.0.0.1:5173/conversations` 登录/进入对话，真实输入“写一份分析报告：使用订单表生成报告”，验证右侧实时跟随、文件切换、复制/下载、刷新回放。

2. **报告过程回放还不是服务端持久化**  
   当前 transcript 回放主要依赖浏览器本地缓存。商用场景需要将 report trace 作为 conversation event 持久化，支持跨设备、历史会话回看和审计。

3. **计划调整不是严格的暂停审批**  
   当前“调整这步”是预填输入框，体验比无入口好，但不等同于 JoyAgent 式暂停/修改/继续。商用建议增加：计划生成后短暂停留，可继续/编辑/跳过某任务。

4. **全量 eval 有看板语义冲突**  
   `MchId` 在看板中既被当作 junk id 禁止，又在细表中被允许作为实体 subject。需要拆分规则：禁止把 `MchId` 作为数值度量，但允许作为明细表/实体排名维度，或调整 eval 期望。

### P1：提升转化与可信度

1. **报告质量需要更强的业务评分器**  
   当前门禁检查目录顺序、薄报告、商户证据遗漏。建议继续增加：数字覆盖率、结论-证据引用对应、章节重复度、无效套话占比。

2. **报告应提供“一键重新生成 / 按建议重写 / 只改标题与口径”**  
   用户拿到报告后常见操作不是下载，而是继续润色。右侧文件页应提供二次生成入口。

3. **右侧工作区需要导出完整包**  
   商用交付往往需要最终 HTML/MD + 中间证据文件 + trace。建议增加“下载报告包”。

4. **状态文案需要产品化**  
   当前工具名仍可见（如 `od_get_data`）。建议默认展示业务文案，调试开关下再显示工具名。

### P2：体验细节

1. 报告目录可点击跳转。
2. 文件页默认显示最终 HTML，但保留“查看证据文件”的次级入口。
3. 浏览器 tab 空态可以解释“本报告未使用外部网页检索”。
4. 长报告右侧需要 sticky 目录或章节导航。
