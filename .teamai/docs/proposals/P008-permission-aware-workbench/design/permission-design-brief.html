P008 · PERMISSION / ASK / DASHBOARD

问数与仪表盘权限 · 详细设计

问数不是独立权限域，而是数据集权限上的消费面。 作品 ACL 管「这张盘谁能打开」；数据 ACL + 行列策略管「能看见哪几行几列」。 两面相交才出数。公开 chartQuery 与对话 internal 查询必须走同一闸。

提案 P008 设计稿 · 未编码 ACL 表 / RLS 2026-08-22 对照 P012 brief §2 改动前写法

1. 背景与问题

P008 已确认消费原则，P009 已确认工作区与四层收敛。 代码停在「角色权限码 + 内存广场 grant + askable 列表」。 问数和质量闸（P012）已经按 askable 收口；看盘出数没有接到同一闸。

现象用户感受根因
分析师 askable 匹配失败会落到「第一个 live 数据集」 问到不该问的表 AskableDatasetService.listAskable 回落
登录即可 POST /api/chartQuery/query 会看盘的人也能打任意 datasetId 公开查询只 @RequireAuth，不验 dataset:use / 看板 ACL
广场 grant 是内存种子 申请通过不能变成真授权 无 od_resource_acl；审批不写库
高保「华东行权限」只是文案 问数和出图都看不到行被裁 无 od_data_policy；Java 不注入 WHERE
viewer 有 dashboard:view 能力码 菜单能进仪表盘，但实例谁能看未定义 能力 RBAC ≠ 资源 ACL
已确认决策（调研 + P008 §2） 不新开问数权限码；不让分享盘反向授数；行列由 Java 确定性注入，禁止 LLM 改写权限 SQL； 用户端不展示工作区；dsh 不持有 DB 密码。RLS 验收 ID 仍在 P009 PR-WS-05，实现按本文闸门接到同一服务。

3. 改造方案 · 四层（明确定义）

与 P012 三大流程相同：这是能力分层，不是新运行时。 权限事实只在 Java；dsh 只消费授权快照并在工具层再拦一次。

确定性 规则/SQL 注入 · LLM 不可扩大权限 · 混合 工具装配+执行 · 人工 审批/授权

L0 · IDENTITY

身份与工作区成员

对标：DataEase oid 进 token · DeerFlow 禁止客户端声明 owner · OD 会话 Cookie

做什么
principal.userId / workspaceId 只来自会话。用户端不切换工作区；管理端才切治理范围。
落点
OD_SESSION、od_workspace_member、AuthContext。internal 调用另加 X-OD-Internal-Token + 用户头，不能单靠内部令牌放大。
不做
完整 IAM / SAML（P009 非目标）。不把工作区做成用户端入口。

L1 · CAPABILITY

能力 RBAC（入口开关）

对标：Quick BI 组织/空间角色 · OD od_permission

做什么
能不能进问数、建盘、管数据集。不回答「哪一张表」。
落点
已有码：conversation:use、dashboard:view|manage、dataset:use|manage、report:view|manage。菜单继续服务端过滤。
不做
不新增 ask:dataset 一类第三套码。问数能力 = conversation:use。

L2 · RESOURCE ACL

资源实例 ACL

对标：DataEase per_auth_busi_* · Metabase collection · Quick BI 协同授权

做什么
哪一张盘 / 哪一份报告 / 哪一个数据集。主体 = 用户 | 用户组 | 角色。
落点
新表 od_resource_acl。数据集动作 use | manage | owner；盘/报告 view | edit | manage | owner。广场「已获权」是 ACL 的视图，不再是第二真相。
不做
不学 DataEase 1/7/9 权重。不把文件夹权限当第一期范围（可后加继承）。

L3 · DATA POLICY

行列策略（挂数据集）

对标：Looker access_filter · Power BI RLS · Quick BI 行列 · DataEase PermissionManage

做什么
每次查询注入行谓词、裁列/脱敏。问数、chartQuery、导出、出板 probe 同源。
落点
新表 od_data_policy。QueryGuard.apply(principal, datasetId, spec|sql) 在 Java 执行前跑。schema 下发前先 CLS。
不做
不让 dsh/LLM 改写带权限 SQL（SQLBot xpack 反面）。本期不做仓内原生 RLS 透传。

4. 判定公式（实现必须按此相交）

# 有效动作（Java EffectiveAccessService，唯一实现）
ask.consume(ds) =
    member(ws)
    ∩ conversation:use
    ∩ acl(dataset, ds) ∈ {use, manage, owner}
    ∩ dataset.live
    ∩ data_policy(ds)          # 执行时注入，不是列表过滤器

dashboard.view(board) =
    member(ws) ∩ acl(dashboard, board) ∈ {view, edit, manage, owner}

dashboard.consume(board) =
    dashboard.view(board)
    ∩ ∀ required ds: acl(dataset, ds) ∈ {use, manage, owner}
    ∩ 每次 chartQuery 再 apply data_policy(ds)

dashboard.write(board) =
    dashboard:manage                         # 能力
    ∩ acl(dashboard, board) ∈ {edit, manage, owner}   # 实例；新建则 create
    ∩ 引用数据集均 ask.consume 的数据面（use）

report.viewStatic = acl(report) ∈ {view…}    # 不查数
report.refreshOrAsk = viewStatic ∩ 相关 ds 的 ask.consume 数据面

accessState:
  forbidden    无作品 ACL          → 列表不可见（404，不暴露存在性）
  unavailable  有作品 ACL，缺 ds use → 元数据卡，无 KPI/缩略图
  available    两面都过            → 可出数
动作L1 能力L2 作品L2 数据集L3 行列
问一句数conversation:use—use注入
打开盘（无数据）dashboard:viewview+——
盘内出数 / 导出dashboard:viewview+每个图 use注入
/board 落 draftdashboard:manageedit+ / createuse规划可见 CLS 后字段
读已发布报告report:viewview+不需要不查
报告继续问数conversation:use—use注入
禁止反向授权 把盘 share 给某人 ≠ 写入 dataset ACL。 把报告 view 给某人 ≠ 进入 askable。 这是 Metabase Blocked 与 P008 §2.1/2.2 的同一句话。

7. 查询闸 · QueryGuard（唯一出数实现）

所有出数：chartQuery、datasetQuery、internal /query/*、CSV 导出、问数 sample。 dsh sql-guard.js 只是第一道（只读 + 表名）；权威在 Java。 

function query(principal, datasetId, specOrSql):
  assert askable 数据面：acl.use(datasetId)     // 看盘路径先过 dashboard.view
  ds = loadDataset(datasetId)                   // 必须同 workspace
  policy = loadPolicies(principal, datasetId)   // user ∪ group ∪ role，user 覆盖 role
  fields = CLS.project(ds.fields, policy.columns)
  if spec:                                      // QuerySpec / encode
      spec.fields = intersect(spec.fields, fields)
      spec.filters = AND(spec.filters, policy.rowTree.bind(principal.attrs))
      return exec(spec)
  if sql:
      checkSqlRead(sql)                         // 与 dsh 同规则，Java 再执行一遍
      tables ⊆ { ds.tableName } ∪ ds.allowedJoins
      wrapped = SELECT fields... FROM (sql) t WHERE rowSql(policy, principal)
      return exec(wrapped)
  never: LLM.rewrite(sql, "add WHERE region=华东")

行策略形状

{
  "kind": "row",
  "subject": { "type": "group", "id": "g-east" },
  "predicate": {
    "and": [
      { "field": "region", "op": "eq", "valueFrom": "user.attrs.region" }
    ]
  }
}
# valueFrom 只允许白名单：user.id / user.email / user.attrs.* （工作区成员扩展属性）
# 字面量只允许管理员配置的枚举，禁止自由 SQL 片段

列策略

effectschema结果行问数
hide字段不出现无该列模型不可引用；引用则 DATASET_COLUMN_FORBIDDEN
mask字段在，标注 masked按规则替换（手机号等）可聚合不可出明文
结构化查询优先 问数主路径继续 od_run_query（QuerySpec）。 od_run_sql 必须外包 + 表白名单；解析失败则拒绝，不降级裸跑。 这是 SQLBot「生成后再校验表名」加上 DataEase「行列进 SQL」，减去 LLM 改写。

8. 表、主体、有效权限算法

8.1 新增表（Flyway，与 V15 并列）

-- 资源实例 ACL。workspace_id 冗余便于隔离扫描。
od_resource_acl (
  id, workspace_id,
  resource_type,          -- dataset | dashboard | report | conversation
  resource_id,
  subject_type,           -- user | group | role
  subject_id,
  action,                 -- dataset: use|manage|owner
                          -- dashboard/report: view|edit|manage|owner
  created_at, created_by,
  UNIQUE (workspace_id, resource_type, resource_id, subject_type, subject_id, action)
)

od_data_policy (
  id, workspace_id, dataset_id,
  kind,                   -- row | column
  subject_type, subject_id,
  effect,                 -- filter | hide | mask
  predicate_json,         -- 行：字段树；列：column+maskRule
  enabled bool,
  created_at, updated_at
)

-- 广场申请落地后写 ACL，不再把 pending 当权限
od_dataset_request (
  id, workspace_id, dataset_id, applicant_id,
  purpose, expire_at, requested_actions,  -- 通常 [use]
  status,                                 -- pending|approved|denied
  decided_by, decided_at
)

8.2 主体合并

subjects(principal, ws) =
    { user: principal.id }
  ∪ { group: g.id | g ∋ principal, g.workspace = ws }
  ∪ { role: r.code | membership(principal, ws, r) }

actions(type, id) =
    { owner }  if creator = principal          # 创建即 owner 行
  ∪ ACL rows matching any subject
  ∪ { manage… } if workspace:admin 且资源 ∈ ws   # 组织管理员短路，对标 DataEase pid=0
  # 平台管理员 platform:admin 跨 ws 仅管理端；用户端问数仍按各 ws ACL，避免超管默认问到所有业务表

# 撤销：删 ACL 行。QueryGuard / askable 不读 >30s 缓存；进程内 Caffeine TTL≤5s，写路径主动 invalidate。

8.3 广场不再是权限源

改动前 WorkspaceGovernanceService 用 AssetSeed.status=granted 决定 actions.contains("ask")。 改动后：

  • 企业资产列表 = 当前用户可见工作区内、已发布、且（已 use 或 标为可申请）的数据集摘要
  • 未获权：名称、负责人、敏感级、申请条件；无 schema、无 sample、无 datasetId 可被拼进 query（可有不透明 assetId）
  • 「添加到我的数据」= 已有 use 的书签，不授新权
  • 审批通过 = INSERT od_resource_acl action=use + 可选 data_policy 模板
