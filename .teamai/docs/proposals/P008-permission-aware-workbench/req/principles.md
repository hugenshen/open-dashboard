# P008 · 已确认的权限原则

需求附录。入口与范围仍以 [README](../README.md) 为准；怎么做见 [design/](../design/)；验收只看 [test/acceptance.yaml](../test/acceptance.yaml)。

## 仪表盘复用数据集权限

- 仪表盘访问必须同时满足资源 ACL（owner / manage / edit / view）和其引用数据集的 `dataset:use`。
- `dashboard:view` / `dataset:use` 是 L1 能力码，不是全量资产授权。新注册默认 `role=analyst` 只获得进模块的能力；看不到他人创建的盘和数据集，除非被授予实例 ACL（创建者自动 owner）。
- 用户有仪表盘 ACL、但任一必需数据集已失去 `use` 时，不得打开或预览数据。
- 工作台可显示不含业务数据的“权限已失效”元数据卡，用于解释资源为何不可用；禁止返回缩略数据、指标值或查询结果。
- 仪表盘权限不反向授予数据集权限。

## 报告是独立静态资源

- 已发布报告保存为可独立查看的静态资源；`report:view` 足以查看已发布静态正文。
- 查看静态报告不要求底层 `dataset:use`，也不触发 `chartQuery` / `datasetQuery`。
- 编辑报告、刷新 live 图、重新生成洞察或“继续问数”时，必须重新校验相关 `dataset:use`。
- 报告查看权不得把底层数据集加入可问集合，不得反向获得仪表盘或数据集权限。
- P008 交付前，P003 仍保持当前 live 图与无权限占位行为；本提案不得被提前写入 requirements。

## 可问数据

- `askableDatasets = conversation:use ∩ dataset:use`。
- 工作台问数框、对话数据上下文和编辑器 SQLBot 必须使用同一可问集合。
- 数据源是管理对象，不是直接可问对象；用户只能消费经过数据集语义层暴露的数据。
- 无可问数据时展示数据广场或申请权限引导，不使用演示数据伪装为用户资产。

## 数据广场

- 数据广场是用户使用端入口，用来回答“企业有哪些资产、哪些已经在我的数据、哪些能申请消费、哪些还在审批”。
- 广场资产至少覆盖数据集、仪表板、数据表组合、文件和 API 数据；第一阶段消费问数仍以已发布数据集为主，其他资产进入我的数据后按各自资源权限消费。
- 管理端「数据集」和「成员权限」负责创建、发布、字段语义、行列策略和授权审批；用户端「数据广场」只做发现、添加到我的数据和申请。
- 未获权资产只展示业务说明、负责人、申请条件和敏感等级，不展示 schema 明细、样例数据、查询结果或可绕过权限的 datasetId。
- 申请通过后，Java 权限中心写入 `dataset:use`、行列策略和必要工具权限；下一次工作台、对话和 SQLBot 刷新同一份 askable 集合。
- 申请中状态必须可见，避免用户重复提交或误以为系统无数据。
